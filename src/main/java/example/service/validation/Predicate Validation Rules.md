# **Полный перечень проверок валидации Predicate Entity → QueryDSL**

## **1. Базовые проверки структуры PredicateDefinition**

- **PredicateDefinition не null**
- **MetaEntity не null** - должна быть указана целевая сущность
- **RootNode не null** - должно быть корневое выражение
- **Имя предиката не пустое** - должно содержать название

## **2. Проверки корневого узла**

- **Корневой узел возвращает BOOLEAN** - результат всего предиката должен быть логическим
- **Отсутствие циклических ссылок** - дерево не должно содержать циклов
- **Глубина дерева ≤ 100** - защита от StackOverflow при рекурсивном обходе

## **3. Проверки для EvaluationOperationNode**

### **Общие проверки операторов:**
- **Левый операнд обязателен** для всех операторов
- **Правый операнд обязателен** для бинарных операторов (EQ, GT, LT, etc.)
- **Правый операнд запрещен** для унарных операторов (NOT, IS_NULL, IS_NOT_NULL)

### **Проверки типов операндов:**
- **Левый операнд соответствует allowedLeftCategory** оператора
- **Правый операнд соответствует allowedRightCategory** оператора  
- **Типы операндов совпадают** для операторов с typesMustMatch = true

### **Специфичные проверки операторов:**

#### **Логические операторы (AND, OR):**
- Оба операнда должны возвращать BOOLEAN
- Поддерживают вложенные логические выражения

#### **Оператор NOT:**
- Только левый операнд, возвращающий BOOLEAN
- Правый операнд должен быть null

#### **Операторы сравнения (EQ, NE, GT, LT, GOE, LOE):**
- Оба операнда сравниваемых типов (COMPARABLE категория)
- Для упорядочивающих операторов (GT, LT, etc.) - только ORDERED типы

#### **Строковые операторы (LIKE, STARTS_WITH, ENDS_WITH, CONTAINS):**
- Оба операнда должны быть STRING типа
- Правый операнд - строковый шаблон/значение

#### **Операторы множеств (IN, NOT_IN):**
- **Левый операнд** - выражение пути или значение
- **Правый операнд** - обязательно ValueConstantNode с множественными значениями
- **Все значения в списке одного типа**
- **Минимум одно значение** в списке

#### **Null-проверки (IS_NULL, IS_NOT_NULL):**
- Только левый операнд
- Правый операнд должен быть null
- Применимы к любым типам (ALL категория)

#### **Пространственные операторы (DISTANCE_SPHERE):**
- **Левый операнд** - POINT тип (геометрия)
- **Правый операнд** - POINT тип (целевая точка)
- **Возвращает DOUBLE** - расстояние в метрах
- **Должен использоваться в сравнениях** (DISTANCE_SPHERE < значение)

## **4. Проверки для PathExpressionNode**

### **Структура пути:**
- **PathExpression не null**
- **FinalPathAttribute не null** - конечный атрибут обязателен

### **Промежуточные атрибуты (навигация):**
- **Все атрибуты принадлежат правильным сущностям** - цепочка entity связей
- **Атрибуты навигации должны быть ENTITY категории** - ссылки на другие сущности
- **Запрещена навигация через PLURAL атрибуты** - только SINGULAR связи

### **Конечный атрибут:**
- **Должен быть BASIC категории** - примитивный тип, не entity ссылка
- **Должен принадлежать последней сущности** в цепочке навигации

## **5. Проверки для ValueConstantNode**

### **Общие правила значений:**
- **Для обычных операторов** - используется одиночное value
- **Для IN операторов** - используются множественные values

### **Проверки одиночного значения:**
- **Value не null**
- **Только одно поле значения заполнено** в соответствии с valueType
- **Тип значения соответствует declared valueType**

### **Проверки множественных значений (IN):**
- **Минимум одно значение** в коллекции
- **Все значения одного типа**
- **Порядок значений сохранен** (используется value_order)

### **Специфичные проверки по типам:**

#### **STRING:**
- stringValue не null
- Остальные поля значений null

#### **BOOLEAN:**
- booleanValue не null
- Остальные поля значений null

#### **INTEGER:**
- integerValue ИЛИ longValue не null (только одно)
- Остальные поля значений null

#### **DOUBLE:**
- doubleValue не null
- Остальные поля значений null

#### **OFFSET_DATE_TIME:**
- offsetDateTimeValue не null
- timestampValue должен быть null
- Остальные поля значений null

#### **POINT:**
- pointValue не null
- Остальные поля значений null

#### **ENUM:**
- **enumValue не null**
- **enumValue.metaEnum не null** - ссылка на перечисление
- **enumValue.name не пустой** - имя значения enum
- **enumValue.storageValue не пустой** - хранимое значение
- Остальные поля значений null

## **6. Проверки целостности данных**

### **MetaAttribute валидация:**
- **Bidirectional связи симметричны** - если A → B, то B → A
- **RelatedAttribute обязателен** для bidirectional атрибутов
- **Entity ссылки валидны** - attributeEntityType существует

### **MetaEnum валидация:**
- **Enum значения имеют metaEnum ссылку**
- **Имена значений не пустые**
- **Storage значения не пустые**

## **7. Проверки совместимости операторов и типов**

### **Строковые операторы:**
- LIKE, STARTS_WITH, ENDS_WITH, CONTAINS - только со STRING типами

### **Числовые операторы:**
- GT, LT, GOE, LOE - только с ORDERED типами (числа, даты)

### **Пространственные операторы:**
- DISTANCE_SPHERE - только с POINT типами

### **Логические операторы:**
- AND, OR, NOT - только с BOOLEAN типами

## **8. Защитные проверки**

### **Производительность:**
- **Максимальная глубина дерева: 100** - защита от бесконечной рекурсии
- **Обнаружение циклических ссылок** - предотвращение зацикливания

### **Целостность:**
- **Все UUID ссылки валидны** - существующие сущности в БД
- **Порядок элементов сохранен** - для коллекций и путей
- **Отсутствие противоречивых состояний** - например, IS_NULL с правым операндом

## **9. Бизнес-правила из доменной модели**

### **Из комментариев к классам:**
- **"Заполняется ТОЛЬКО ОДНО поле"** - для PredicateNodeValue
- **"Для ENUM используется enumValue, stringValue = null"** - типобезопасность enum
- **"Конечный атрибут должен быть BASIC типа"** - для PathExpression
- **"Bidirectional связь должна быть симметричной"** - для MetaAttribute
- **"IN оператор требует VALUE_CONSTANT с множественными значениями"** - специфика IN

### **Из примеров данных:**
- **Поддержка сложных вложенных выражений** - как в complex-advanced примере
- **Комбинация пространственных и логических операторов**
- **Навигация через несколько entity связей**
- **Использование всех типов данных** - строки, числа, даты, enum, геометрия

Все эти проверки обеспечивают корректное преобразование Predicate Entity в QueryDSL predicate и гарантируют, что результирующее выражение будет выполнимо и типобезопасно.
