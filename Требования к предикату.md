Требования к сущностям для хранения предикатов
1. Базовые принципы
   Использовать стратегию явных связей для бинарных операторов

Отказ от orderIndex - порядок определяется структурой связей

Поддержка сложных вложенных выражений любой глубины

Типобезопасность через четкие связи между узлами

2. Enum'ы должны поддерживать
   java
   NodeType: LOGICAL_OPERATOR, COMPARISON_OPERATOR, ATTRIBUTE_REFERENCE, VALUE_CONSTANT
   OperatorType: AND, OR, NOT, EQ, NE, GT, LT, GOE, LOE, LIKE, CONTAINS, IN, BETWEEN, IS_NULL, etc.
   AttributeType: STRING, INTEGER, BOOLEAN, DATE, etc. (брать из существующих MetaAttribute)
3. Структура сущностей
   PredicateDefinition
   Ссылка на MetaEntity (к какой сущности применяется предикат)

Прямая ссылка на корневой узел (rootNode)

Мета-информация (название, описание, активность)

PredicateNode
Разные типы связей для разных операторов:

leftOperand, rightOperand - для бинарных (AND, OR)

operand - для унарных (NOT)

comparisonAttribute, comparisonValue - для сравнений (EQ, GT, etc.)

comparisonAttribute, inValues - для IN оператора

betweenFrom, betweenTo - для BETWEEN оператора

Поддержка ссылок на MetaAttribute

Хранение константных значений

PredicateNodeValue
Только для хранения значений в IN операторе

Без orderIndex - порядок не важен

4. Важные детали
   Каскадное сохранение/удаление всех связанных узлов

Lazy fetching для связей с MetaEntity/MetaAttribute

Четкое разделение ответственности между типами узлов

Поддержка всех операторов из примера: ==, !, ||, &&, IN

5. Готовность к интеграции
   Учесть существующие MetaEntity и MetaAttribute пользователя

Обеспечить совместимость типов данных

Подготовить конструкторы/фабричные методы для удобного создания узлов

Жду MetaEntity и MetaAttribute пользователя для точной настройки типов и связей.
